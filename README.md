# Silmä

This is a streamlined raw photo developer for Linux (C++/Qt 6), modelled on Lightroom Classic's
Develop module: cull, develop and export the photos of a trip, with lens profiles, AI denoise
and heal, HDR and panorama merges. (*Silmä* is Finnish for "eye".)

This is a vibecoded project, with the initial version done by Claude Opus 5.5 medium in three
days.  I haven't even really looked at the code yet; I'm not well familiar with modern C++, even
less so with Qt, and I have pretty much zero idea about the mathematics involved.  But such
an application would be extremely useful for me; I use Lightroom a lot to process photos for
my blog from my field trips, but there are way too many annoying things about it: the subscription fee,
sluggishness, lack of Linux version; I had to keep around a Windows installation for Lightroom
alone.  There are of course Linux analogues, and I did try to use Darktable at some point, but
the UI seemed too annoying and alien to be honest; I've been using Lightroom for something like
15 years, and even though I mostly only ever use a small subset of its features, muscle memory is
just too strong.  So the point here is to keep UI as Lightroom-like as possible, but do a clean
greenfield Linux reimplementation with only the features I actually use.  And it seems to be
working pretty nicely, and it's really much faster than Lightroom.

I do not expect this project to be particularly useful or interesting to anyone other than myself
(as of October 2026, various vibecoded replacements of Adobe suite seem to be springing up around
anyway, although of course most of them will probably have too many features to be properly
polished, and will be abandoned almost immediately anyway).  Honestly at this point if you want to
have something like that, you might as well grab a Claude Max subscription yourself and make your
own version over a few evenings.

The initial release is about 17 kLOC of C++.  Claude was smart enough to pull various relevant
dependencies (libraw, exiv2, lensfun, lcms2, opencv and onnxruntime most importantly) without
reinventing the wheel where not necessary; also two third-party open source AI models are used,
for heal and denoise tools.  Only the Arch Linux PKGBUILD is included, since this is what I use.

## Building

On Arch, `packaging/arch/PKGBUILD` builds a package (`silma-git`) from the GitHub repository:

    cd packaging/arch && makepkg -si

Dependencies (Arch): `cmake ninja qt6-base qt6-svg libraw exiv2 lensfun libjpeg-turbo libtiff libjxl libheif sqlite lcms2 opencv onnxruntime-cpu`.
Optional: `kcolorscheme` (KDE color schemes: the app defaults to Breeze Dark and offers the installed schemes under View → Color Scheme; without it a built-in dark palette is used).

For GPU-accelerated AI denoise install `onnxruntime-opt-rocm` (AMD) or `onnxruntime-cuda`
instead of `onnxruntime-cpu`; Silmä picks the GPU provider automatically
(`SILMA_AI_PROVIDER=cpu|rocm|migraphx|cuda` overrides).

    cmake -S . -B build -G Ninja
    ninja -C build
    ctest --test-dir build        # GUI test needs QT_QPA_PLATFORM=offscreen when headless
    sudo cmake --install build    # binary, desktop entry, icon and .silma file type (then update-mime-database)

The icon (`data/silma.svg`) is generated by `data/make-icon.py` (needs python-shapely), which
keeps it to the SVG subset Qt renders.

The binary is `build/src/app/silma`.

## Concepts

- **Batch**: a `*.silma` file (sqlite) holding everything about one trip: imports, photos,
  develop settings, full edit history and UI state. Schema is versioned and migrated.
- **Import**: a folder (by default `YYYY-MM-DD` next to the batch file) into which photos are copied.
- Editing is non-destructive. Every change is a history step; undo/redo moves within it.

## GUI

`silma` opens the last batch; `silma TRIP.silma` opens a specific one.
Keyboard: Left/Right navigate, X/U reject/unreject, Z, Space or click toggles fit/1:1, wheel zooms,
`\` before/after, C compare, R crop tool, Q heal tool, Ctrl+I metadata, Ctrl+U auto tone, Ctrl+[ / Ctrl+] rotate 90° left/right (all selected; exports are physically rotated, Reset keeps the rotation), Ctrl+Z / Ctrl+Shift+Z undo/redo,
W white balance picker (click a neutral point), Ctrl+Shift+C/V copy/paste settings (pasting asks which settings, Ctrl+Alt+Shift+V reuses the previous choice; heal spots are not pasted), Ctrl+Tab / F6 / F7 / F8 hide panels (Tab moves between controls), the pin button in a panel title (or Shift+F6 / F7 / F8) switches the filmstrip, left or right panel to auto hide & show (the panel slides in while the mouse is at that window edge). Delete moves the selected photos to the trash or only excludes them from the batch (asks first; the files stay on disk). Right-click a photo in the filmstrip for reject, settings, rotate, merge, export, delete and file actions.

## CLI (also meant for AI agents)

Every command accepts `--json` for machine-readable output. Set the batch with `-b FILE`
or the `SILMA_BATCH` environment variable. Photos are referred to by id, `import/FILE`,
a unique file name, or `all`.

    silma create trip.silma
    silma -b trip.silma import /media/card/DCIM --split-by-date
    silma list --import 2026-07-05
    silma meta 12 --all
    silma keys                              # every settable develop key and range
    silma set 12 exposure=0.7 shadows=30    # one history step
    silma auto 12 --tone --wb
    silma undo 12; silma redo 12; silma history 12
    silma render 12 preview.jpg --size 1600 # look at the result
    silma render 12 crop.jpg --size full --roi 0.4,0.4,0.2,0.2   # 1:1 detail
    silma sync 12 13 14 --only wb,exposure
    silma reject 15; silma delete-rejected --yes
    silma export --import 2026-07-05 --to ~/Pictures/out --long-edge 2048
    silma show 12                           # make a running GUI jump to photo 12
    silma upright 12 --mode vertical        # auto perspective (+ constrained crop)
    silma turn 12 13 right                  # rotate 90° (left, right, 180)
    silma exclude 14                        # remove from the batch, keep the file
    silma delete 15 --yes                   # file to the trash, remove from the batch
    silma ai-denoise 12                     # AI noise reduction -> new DNG photo
    silma hdr 20 21 22                      # bracketed exposures -> HDR DNG
    silma pano 30 31 32 33                  # cylindrical panorama DNG
    silma ai-models                         # models, download state, GPU providers
    silma heal 12 0.31,0.62,0.03            # generative heal at a spot of the rendered output

The GUI picks up changes made through the CLI within a second.

For automation, `SILMA_SCREENSHOT=out.png [SILMA_SCREENSHOT_DELAY=ms] silma` grabs the
window and exits (works with `QT_QPA_PLATFORM=offscreen`).

## JPEG and HEIC photos

Besides raw files, JPEG and HEIC/HEIF photos (e.g. from phones) can be imported. They are
decoded with their colour profile (Display P3 on iPhones) and with Silmä's default look
undone, so default settings show them unchanged and every control works as on raws. They
start without sharpening, colour noise reduction and lens corrections (the camera did those);
AI Denoise works on raws only. The JPEG of a RAW+JPEG pair (same name, same folder, imported
together) is left out: the raw is imported. HEIC HDR gain maps are ignored (the SDR image is used).

## Hot pixels

Hot and stuck sensor pixels are removed from the raw mosaic of every photo before
demosaicing (and before AI denoise): a sample far above all of its 16 nearest samples is
replaced with the median of its own colour's neighbours. `silma probe` reports how many;
`SILMA_KEEP_HOT_PIXELS=1` keeps them (for comparing).

## Export

Exports are rendered at full resolution (so Develop sharpening works at the scale it is set
for), downscaled with a Lanczos filter in linear light and then given output sharpening for
screens at the exported size, like Lightroom's: None, Low, Standard (default) or High
(`export --sharpen`).

## Derived photos

The Merge to HDR and Merge to Panorama dialogs make a quick, smaller preview as soon as they open
(a second or two; the panorama with its auto crop marked, the HDR merge again when alignment or
ghost removal is switched), so a failing or poor merge shows before the real one
(`silma pano|hdr ... --preview out.jpg` for the same from the command line).

AI denoise, HDR and panorama results are written as linear (floating point) DNGs next to the
source photo, added to the batch and developed like any raw. Panoramas include a DNG transparency
mask of the stitched area, so Auto Crop works on them later too (e.g. after `pano --no-crop`). AI models are downloaded on first
use to `~/.local/share/silma/models` (RawNIND for denoise; LaMa for heal).

AI denoise uses RawNIND by default (Benoit Brummer's UtNet2, GPL-3.0, trained on real camera
noise; ONNX export from darktable). On Bayer sensors it works on the raw mosaic and demosaics at
the same time (about 8 s per 24 MP photo on a Ryzen 5 8600G); on others (X-Trans, Foveon, linear
DNGs) a second variant denoises the demosaiced image in linear Rec.2020 (about 25 s).
`SILMA_AI_FORCE_LINEAR=1` uses that variant on Bayer sensors too (for comparing).
The AI Denoise dialog previews a 1:1 square of the current photo with its settings (drag it, or
click the overview, to look elsewhere; press and hold to see the original); the strength slider
updates it right away.
AI Heal (Q) fills a clicked spot or a dragged brush stroke; its fills are stored in the batch, so
heals are ordinary undoable edits. LaMa works at 512×512, so a heal may span at most a fifth of the
photo's long edge, and larger ones come out softer.

JPEG XL compressed DNGs (DNG 1.7, e.g. Lightroom's HDR and panorama merges) are decoded with
libjxl, as LibRaw cannot unpack them; their transparency masks (uncovered panorama areas)
come out black, and Auto Crop finds the largest fully covered rectangle (any aspect ratio
unless the crop already has a locked one). JPEG XL compressed mosaic (CFA) DNGs are not supported yet.


### Measuring AI performance

For measuring: `SILMA_AI_THREADS` sets the inference threads (default: one per physical core),
`SILMA_AI_LAYOUT=1` enables ONNX Runtime's blocked layout transform (off: its layout
conversions cost more than they save) and `SILMA_AI_PROFILE=PREFIX`
writes ONNX Runtime's per-operator profile.
